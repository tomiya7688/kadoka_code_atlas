# Kadoka Code Atlas ワークフロー

## 作業開始時

1. リポジトリの場所を確認し、`git status --short --branch` で作業ツリーを確認する。既存の未コミット変更は保持し、作業対象と混ぜない。
2. リモートの最新を必ず確認する。

   ```powershell
   git fetch --prune origin
   git rev-list --left-right --count main...origin/main
   git pull --ff-only origin main
   ```

   `main` がローカルより進んでいる場合は、未送信のローカルコミットを確認したうえで `git merge --no-edit origin/main` を実行する。競合は内容を確認して解消し、`git status` とテストで取り込み結果を確認する。リモート履歴を force push で上書きしない。
3. `next_issue.bat` を実行して、GitHub Issues から現在の優先 Issue を選ぶ。
4. `AGENTS.md` と、Issue に対応する `docs/specs/` の仕様だけを読む。

## 実装時

- Issue の範囲を小さく分け、1 回の変更を独立して検証できる単位にする。
- 言語固有の解析は `Src/languages/` に置き、生成処理や UI と分離する。
- 既存コメントと無関係な書式を保持し、実行意味を変更しない。
- ルールベースで動作する経路を保ち、LLM を使う場合も任意の経路として分離する。

## 検証と完了

- 変更に対応するテストを実行し、構文・生成結果・冪等性を確認する。
- テストが環境上実行できない場合は、代替検証と未実行の理由を記録する。
- Issue の完了条件をすべて満たした場合だけ `pull_request.bat` を実行する。これはテスト、コミット、push、Pull Request 作成を行う。
- Issue の一部だけを実装した場合は、ローカルコミットまでに留め、残りの完了条件を次の作業として明示する。
